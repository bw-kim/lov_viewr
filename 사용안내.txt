실행: index.html을 더블클릭해 Edge 또는 Chrome에서 여세요. 설치·인터넷 연결·서버 실행이 필요 없습니다.
파일 불러오기: 로그 파일을 여러 개 선택하거나, 폴더 불러오기로 수집 폴더를 선택하세요.
GZ / ZIP / TAR / TAR.GZ 파일도 읽습니다. 지원하지 않는 압축은 별도로 풀어 넣으세요.

먼저 왼쪽에서 원본 서버의 시간대와 syslog 연도를 확인하세요.
기본 해석: 시간대 없는 기록 UTC, 연도 없는 기록 2026. 화면 표시: 한국 시간.
서버 기록이 한국 시간이라면 ‘시간대 없는 기록’을 한국으로 바꾼 뒤 ‘해석 설정 적용’을 누르세요.
연말/연초를 걸치는 연도 없는 기록은 같은 연도로 해석하므로 따로 검토해야 합니다.

검색 단어는 공백으로 나누면 기본적으로 모두 포함하는 기록을 찾습니다.
‘핵심 기록’은 SSH·파일 이름변경/삭제·MySQL 기록을 먼저 보여줍니다.
‘들어온 SSH’는 계정 검사, 인증, 로그인, 세션 시작/종료를 구분합니다.
‘나간 SSH’는 이 서버에서 SSH 클라이언트 도구가 실행된 흔적입니다.
‘이름변경·삭제’는 audit 시스템 호출의 결과와 이전·이후 경로를 표시합니다.
‘MySQL’은 연결·질의·덤프 도구 흔적을 보여줍니다.
분류되지 않은 audit 기록은 ‘전체 원문’에서 봅니다.
IP, 계정, 파일명 버튼이나 시간 분포 막대를 눌러 범위를 좁히세요.
‘조회 초기화’는 검색어·기간·파일 선택·종류·정렬을 처음 상태로 돌립니다. 로그와 메모는 유지합니다.
기록을 누르면 원문·시간 근거·출처·행 번호·같은 파일의 앞뒤 기록을 볼 수 있습니다.
별 표시와 메모를 넣은 후 ‘메모 저장’을 누르세요. 기록은 브라우저 탭을 닫으면 사라집니다.
‘현재 결과 CSV’는 필터된 모든 기록을 내보냅니다. 페이지에 보이는 기록만 내보내는 것이 아닙니다.

분류는 문자열 단서입니다. 명령의 성공·유출 여부를 자동 판정하지 않습니다.
덤프가 원격 DB 클라이언트에서 이루어졌다면 서버에 덤프 파일명은 없을 수 있습니다.
파일명·문자열·타임스탬프를 다른 증거와 대조하세요.
원본 파일을 수정하지 않으며, 외부 네트워크에 업로드하지 않습니다.

한도: 파일/압축 해제된 파일당 256 MiB, 한 번 불러오기당 50만 기록.
한도를 넘거나 해석하지 못한 자료는 ‘불러오기 결과’에서 확인하세요.
암호화/분할/ZIP64/일부 TAR/중첩 ZIP은 별도로 풀어야 합니다.
UTF-8이 기본이며 깨진 문자는 EUC-KR/CP949 등 인코딩을 선택하고 다시 읽으세요.

바이너리 journal / wtmp / btmp / MySQL binlog 자체는 직접 읽지 않습니다.
journalctl / last -Fai / lastb -Fai / mysqlbinlog로 수집한 텍스트 출력을 넣으세요.
연도·시간대·해석할 수 없는 날짜를 점검한 뒤 조사 타임라인에 사용하세요.

다른 로그 형식을 조절하기:
상단 ‘로그 형식 조절’에서 대상 파일명을 지정하세요. 별표(*)로 여러 파일을 선택할 수 있습니다.
날짜 형식 예: DD/MM/YYYY HH:mm:ss / YYYY.MM.DD HH:mm:ss / MMM D HH:mm:ss
epoch 형식: UNIX_S(초), UNIX_MS(밀리초), UNIX_US(마이크로초)
날짜가 문장 속 특정 위치에 있으면 선택적으로 정규식을 지정할 수 있습니다.
원문을 붙여넣고 ‘미리보기’로 확인한 다음 ‘등록하고 다시 읽기’를 누르세요.
규칙별로 원본 시간대와 연도 없는 기록의 연도를 따로 지정할 수 있습니다.
history.txt처럼 파일명이 달라 자동 인식되지 않는 경우 읽기 방식을 셸 history로 바꿔주세요.
각 규칙은 위에서부터 적용되며, 파일명에 맞는 첫 번째 규칙을 사용합니다.
형식 저장/형식 열기로 설정을 다른 조사에 재사용할 수 있습니다.
