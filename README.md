# lov_viewr — 사고 로그 열람실

리눅스 침해사고 조사 자료를 한 화면에서 읽는 로컬 로그 뷰어입니다. 여러 파일을 시간순으로 모아 IP, 계정, 파일명, 명령어로 검색할 수 있습니다.

## 실행

`index.html`을 Chrome 또는 Edge에서 여세요. 별도 설치나 서버, 외부 라이브러리가 필요하지 않습니다. 먼저 **예시 보기**를 눌러 화면을 확인할 수 있습니다.

파일은 브라우저 안에서 읽으며 원본을 수정하지 않습니다. 페이지는 외부 연결을 차단하는 Content Security Policy를 포함합니다.

## 기능

- 여러 파일 또는 폴더를 불러와 시간순으로 통합합니다.
- 접속·종료, 인증 실패, 권한 변경, 덤프 명령, 압축, 전송 도구 등의 문자열 단서를 필터링합니다.
- IP, 계정·UID, 덤프·압축 파일명 단서를 추출합니다.
- 기록을 누르면 원문, 시각 근거, 출처, 행 번호, 같은 파일의 앞뒤 기록을 확인합니다.
- audit 기록은 같은 파일의 동일 epoch·serial을 묶고, 16진수 명령 인수를 별도로 해석합니다.
- 중요 표시와 메모를 저장하고 현재 검색 결과 전체를 CSV로 내보냅니다.
- 밝은 화면·어두운 화면과 글자 크기를 선택할 수 있습니다.
- 원본 파일의 SHA-256 계산을 선택할 수 있습니다.

단서 분류는 문자열 매칭입니다. 명령 실행의 성공이나 데이터 유출을 자동으로 입증하지 않습니다. 원격 DB 클라이언트에서 덤프했다면 서버에 덤프 파일명이 없을 수 있습니다.

## 지원 자료

일반 텍스트 로그, syslog 형식의 `auth.log`·`secure`, raw audit, journal JSONL, MySQL 날짜 형식, 웹 접근 로그, bash history epoch, `last -F` 등의 영문 날짜를 해석합니다. 날짜를 읽지 못한 기록도 **시간 미확인**으로 남깁니다. 일반 CSV·파일 목록은 원문을 열람하며 각 열의 의미는 자동으로 판정하지 않습니다.

GZ, ZIP, TAR, TAR.GZ를 브라우저에서 읽습니다. 암호화 ZIP, ZIP64, 분할 압축, 중첩 ZIP, 일부 TAR 및 XZ·BZ2·ZST·7Z·RAR 등은 별도로 풀어야 합니다. 지원하지 않거나 누락된 자료는 **불러오기 결과**에 표시됩니다.

바이너리 journal, wtmp/btmp, MySQL binlog 자체는 직접 읽지 않습니다. `journalctl`, `last -Fai`, `lastb -Fai`, `mysqlbinlog` 등으로 수집한 텍스트 출력을 넣으세요. MySQL binlog는 일반적인 SELECT 덤프를 기록하는 용도가 아닙니다.

## 시간 설정

기본값은 연도 없는 기록 **2026년**, 시간대 없는 기록 **UTC**, 화면 표시 **한국 시간(UTC+09:00)**입니다. 실제 서버의 시간대와 수집 연도를 확인한 뒤 왼쪽에서 바꾸고 **해석 설정 적용**을 누르세요. 좁은 화면에서는 **파일·시간 설정 보기**를 눌러 설정을 엽니다.

원문에 epoch 또는 시간대가 있으면 해당 값을 사용합니다. 연도나 시간대가 없는 기록에는 설정값을 적용하고 상세 화면에 가정을 표시합니다. 연말·연초를 걸치는 연도 없는 기록은 자동으로 연도를 추정하지 않으므로 파일별 규칙을 지정하거나 자료를 나눠 확인하세요.

## 다른 형식 조절

상단 **로그 형식 조절**에서 대상 파일명과 읽기 방식을 지정합니다. `*custom*`, `*.txt`처럼 별표를 쓸 수 있습니다. 파일명에 맞는 첫 번째 규칙을 적용합니다.

| 원문 날짜 예시 | 날짜 형식 |
| --- | --- |
| `04/10/2026 12:35:00` | `DD/MM/YYYY HH:mm:ss` |
| `2026.10.04 12:35:00` | `YYYY.MM.DD HH:mm:ss` |
| `2026-10-04T12:35:00.123Z` | `YYYY-MM-DDTHH:mm:ss.SSSZZ` |
| `Oct  4 12:35:00` | `MMM D HH:mm:ss` |
| epoch 초 | `UNIX_S` |
| epoch 밀리초 | `UNIX_MS` |
| epoch 마이크로초 | `UNIX_US` |

`YYYY`, `YY`, `MM`, `MMM`, `DD`/`D`, `HH`/`H`, `mm`, `ss`, `SSS`, `ZZ`를 사용합니다. 규칙마다 원본 시간대와 연도 없는 기록의 연도를 지정할 수 있습니다.

날짜가 특정 위치에 있으면 선택적으로 날짜 추출 정규식을 입력합니다. 예를 들어 `eventTime=([^;]+)`는 첫 번째 괄호에 해당하는 값을 날짜로 읽습니다. 원문을 붙여넣어 **미리보기**로 확인한 다음 **등록하고 다시 읽기**를 누르세요. 규칙과 맞지 않는 기록은 시간 미확인으로 남깁니다.

파일명이 다른 history 텍스트는 읽기 방식을 **셸 history 형식**으로 지정할 수 있습니다. **형식 저장/형식 열기**로 규칙을 재사용합니다.

## 저장과 한도

기록과 메모는 현재 탭에 유지됩니다. 탭을 닫거나 새로고침하기 전에 **메모 저장**과 **현재 결과 CSV**를 사용하세요. 메모는 동일한 출처·행·원문과 연결합니다. CSV에는 원문, 출처, 행 번호, 시각 근거, 메모를 포함하고 수식으로 해석될 수 있는 셀은 텍스트로 처리합니다.

파일 및 압축 해제된 파일당 **256 MiB**, 한 번 불러오기당 **50만 기록**이 한도입니다. 초대형 행과 여러 행 기록은 **1 MiB**를 기준으로 제한하거나 분리하고 결과에 표시합니다. 많은 자료를 추가하면 브라우저 메모리를 사용합니다. 큰 자료는 나눠 불러오세요.

실제 사고 자료는 이 저장소에 넣지 마세요. 로컬 `evidence/` 또는 `logs/` 폴더는 Git에서 제외됩니다.

## 검증

`smoke-check.mjs`는 뷰어 안의 실제 해석 코드를 사용해 날짜·시간대, SSH 단서, audit 묶기·16진수, 셸 기록, journal 원문 보존, last·웹 로그, 사용자 형식·정규식·epoch, GZ·ZIP·TAR.GZ, 해시, 바이너리 제외, CSV 처리를 확인합니다.

```sh
node smoke-check.mjs
```

`check-fixtures/`에는 검증용으로 만든 가상 로그만 들어 있습니다. 주소는 문서용 예시 주소입니다. 실제 서버 로그는 포함하지 않습니다. 화면에서도 예시 자료임을 표시합니다.
